# 会社の言葉図鑑（仮称）情報収集の設計（たたき台）

作成：2026/11/08　状態：たたき台。名前とAPIキーの置き場所が決まったら確定版にする。

サイトの見せ方はあとで決める。この文書では、何をどこから集め、どう確かめ、どう点検するかだけを決める。基本の流れはコミュニティ事例図鑑とあしたの転機観測所に合わせる（スプレッドシートに集める → Claudeが定期実行で収集・公開判定・点検 → 公開用タブをサイトが読む）。

## 1. 集めるもの

会社が自社の目指す姿や大切にすることとして掲げている言葉を集める。呼び名は問わない（ミッション、パーパス、志、存在意義、綱領、ステートメント、フィロソフィー、ウェイ、バリュー、行動指針など）。

言葉は3つの層に分けて記録する。

| 層 | 例 | 記録する内容 |
|---|---|---|
| いちばん上 | ミッション、パーパス、綱領 | 原文どおり |
| 目指す姿 | ビジョン | 原文どおり |
| 価値観 | バリュー、行動指針、Way | 項目の名前だけ原文どおり。説明文は書き写さない |

試しに20社集めたところ、言葉は会社ごとによく変わることが分かった（20社中8社以上で改定の記録あり）。そこで、**会社ごとに1行ではなく、言葉ごとに1行**で記録し、使い始めと使い終わりの時期を持たせる。改定があったら古い行を「使い終わり」にして新しい行を足す。こうしておけば、今の言葉の一覧も、言葉の変わり方の記録も同じデータから作れる。

## 2. どこから集めるか

出典は次の順に優先する。

1. 会社の公式サイトの理念ページ（直接開いて読む。試しに開いた5社では4社がそのまま読めた）
2. 会社の公式発表（理念やミッションの刷新を知らせるニュースリリース）
3. 有価証券報告書の「経営方針」の欄、統合報告書（上場企業のみ）
4. 会社が自分で書いた採用ページ（Wantedly、HERPなどの会社ページ。スタートアップ向け）

就活サイト、求人サイト、まとめ記事などの二次情報は、候補を見つけるためにだけ使い、出典にしない。試しに集めた20社では二次情報どうしで食い違う例があった（メルカリのバリューの数、リクルートのミッション）。

有価証券報告書はEDINETのAPIを使えば全上場企業から同じ形で取れる。ただし利用者登録をしてAPIキーを取る必要がある（無料、黒田さんの手作業が1回だけ必要。試しにキーなしで呼ぶと401が返った）。

## 3. 候補の見つけ方（チャネル）

| チャネル | 中身 | 向いている使い方 |
|---|---|---|
| 上場企業の一覧 | JPXが公開している上場銘柄の一覧を、業種ごとに上から順に当たる | 件数を着実に増やす |
| 刷新の発表 | ニュースリリースで「ミッション 刷新」「パーパス 策定」「バリュー 改定」などを探す | 改定の記録を拾う。新しい行が生まれやすい |
| 自分の図鑑からの芋づる | コミュニティ事例図鑑と観測所に載っている会社 | 黒田さんの他の図鑑とつなげる |
| スタートアップ | 採用ページのある会社、資金調達の発表に載る会社 | 若い会社の言葉を拾う |
| 話題になった言葉 | 記事や書籍で取り上げられた理念 | 知名度のある例を押さえる |

## 4. 載せる基準

- 公式の出典で、言葉を一字一句確かめられたものだけを載せる。二次情報でしか確かめられないものは保留にする。
- 会社（法人）が掲げている言葉に限る。事業部やブランド単位の言葉は、別の行として載せてよい（「対象」の列で区別する）。
- 書き写すのは、いちばん上の言葉、ビジョン、価値観の項目名まで。どれも短い句なので、出典を添えて引用として扱う。価値観の説明文や、理念を解説した文章は書き写さない。
- 公式の出典どうしで食い違うときは、日付の新しいほうを使い、内部メモに両方を残す。

## 5. スプレッドシートの形（案）

### 会社一覧（1社1行）

ID / 会社名 / 読み / 業種 / 上場区分 / 設立年 / 従業員数の区分 / 公式サイト / 理念ページのURL / 確認日 / 確認状況 / 黒田メモ（AIは書かない） / 内部メモ

### 言葉一覧（1つの言葉で1行）

ID / 会社ID / 対象（会社全体・事業部・ブランド） / 層（いちばん上・目指す姿・価値観） / 会社での呼び名（原文どおり） / 言葉（原文どおり） / 英語版（あれば） / 使い始め（年月） / 使い終わり（年月。今使っているなら空欄） / 前の言葉のID / 出典URL / 出典の種類 / 出典の日付 / 確認日 / 確認状況 / 追加日 / 収集元 / 内部メモ

価値観は1項目を1行にする（例：日立の「和」「誠」「開拓者精神」で3行）。項目の数や並び順も数えられるようにするため。

### そのほかのタブ

コミュニティ事例図鑑と同じく、探索ログ、除外リスト、点検ログ、入力ルール、選択肢、公開用（数式で抜き出す。書き込まない）を置く。

## 6. 定期実行の流れ

コミュニティ事例図鑑の定期実行と同じ順番にする。

- **A. 公開判定**：「未確認」の行の出典を開き直し、言葉を一字一句照らす。合っていれば「確認済み」。
- **B. 点検**：「確認済み」の会社の理念ページを開き直し、言葉が変わっていないかを確かめる。変わっていたら、古い行の「使い終わり」を埋め、新しい行を「未確認」で足す。この図鑑では、点検がそのまま改定の記録集めになる。
- **C. 収集**：チャネルを2〜3つ回って新しい会社を足す。
- **D. 報告**：足した件数、改定を見つけた会社、保留の理由をまとめる。

実行の頻度、1回に足す件数、点検の周期は、最初の1週間を見てから決める。目安として、1日2回、1回10社、点検は90日周期で始める。

## 7. 数えるために今から気をつけること

サイトの目玉は「よく使われる言葉」や「増えた言葉」になる見込みなので、集める段階で次を守る。

- 言葉は原文どおりに書く（全角・半角、記号、改行も変えない）。表記をそろえるのは、数えるときに別の処理でやる。
- 使い始めの時期は、出典に書いてあるときだけ埋める。推測で埋めない。
- 英語だけの言葉（「WOW Our Users!」など）も、そのまま1行として載せる。

## 9. EDINETで確かめたこと（2026/11/08）

- APIキーは黒田さんのMacのキーチェーンに、サービス名 `EDINET_API_KEY` で入っている。使うときは `security find-generic-password -a "$USER" -s EDINET_API_KEY -w` で読み出し、画面やファイルに出さない。GitHub Actionsで動かすことになったら、Secretsにも登録する。
- 書類一覧（`/api/v2/documents.json?date=…&type=2`）は動いた。2026/06/26 の1日分で書類1,267件、有価証券報告書217件（うち上場企業130件）。
- 書類本体はCSV（`type=5`）で取れる。「経営方針、経営環境及び対処すべき課題等」の欄は `jpcrp_cor:BusinessPolicyBusinessEnvironmentIssuesToAddressEtcTextBlock` に入っている。
- 試しに読んだコナミグループの有価証券報告書には、「2026年４月より従来の企業理念を発展させ、『価値ある時間』をともにを新たにパーパスとして掲げ」とあった。言葉と、改定の時期の両方が取れる。
- 有価証券報告書は年に1回なので、6月下旬（3月決算の会社の提出時期）にまとめて取り込むと効率がよい。
