# 会社のことば研究所 データ収集・点検

版：2026-11-08b（実行中の目印、層の決め方、除外リストのEDINETコードを反映）

黒田悠介さんのサイト「会社のことば研究所」に載せる、会社が掲げる言葉（ミッション、パーパス、志、綱領、ビジョン、バリュー、行動指針など）を、Googleスプレッドシートに集めて管理する。言葉は1つで1行にし、使い始めと使い終わりを持たせる。言葉が変わったら古い行を残したまま新しい行を足す。こうしておくと、今の言葉の一覧と、言葉の移り変わり（サイトの「言語史」コーナー）を同じデータから作れる。

モードは2つ。依頼に「ふりかえり」「週次」「状況報告」があれば **週次ふりかえり**、それ以外は **定期実行**（A 公開判定 → B 点検 → C 収集 → D 報告）。「EDINETから取り込んで」だけの依頼は、C の EDINET のチャネルだけを行う。

## 載せる基準

`入力ルール` タブが基準。要点は次のとおり。

- 載せるのは、会社が自社の目指す姿や大切にすることとして掲げている言葉。呼び名は問わない。
- 層は3つ。`いちばん上`（ミッション、パーパス、志、綱領、経営理念など、その会社の言葉の頂点にあるもの）、`目指す姿`（ビジョン）、`価値観`（バリュー、行動指針、Way、信条など）。社是・社訓・経営理念などが並ぶときは、呼び名ではなく形で決める：短い項目が複数並ぶもの（「〜しよう」が3つ、など）は価値観、1つの文で会社の存在意義や使命を述べるものはいちばん上（2026/11/08 黒田さんがまかせた判断）。
- 言葉は出典のとおりに書く（全角・半角、記号、句読点も変えない）。原文の改行は、そこに句読点や空白がなければ詰める。価値観は項目の名前だけを1項目1行で書き、G列に順番を書く。項目の説明文や、理念を解説した文章は書き写さない。言葉そのものが長い文（綱領など）の場合は、そのまま書いてよい。
- 出典は公式のものだけ：会社の公式サイト、公式発表（ニュースリリース）、有価証券報告書、統合報告書、会社が自分で書いた採用ページ。就活サイト、求人サイト、まとめ記事は候補探しにだけ使う。
- 使い始め・使い終わりは、出典に時期が書いてあるときだけ `2026/04` の形で書く。推測で埋めない。
- 公式の出典どうしで言葉が食い違うときは、日付の新しいほうを使い、内部メモに両方を書く。
- 事業部やブランドの言葉は、D列を `事業部` か `ブランド` にして別の行で載せてよい。グループ会社は、上場している会社を単位にする。

## ツールと書き方

- 最初に `TZ=Asia/Tokyo date +%Y/%m/%d` で今日を確かめる。日付は `2026/11/08` の形で日本時間。
- Google Sheets コネクタを使う。書き込む前に `anthropic-skills:google-workspace` を読む。文章（内部メモ、報告）を書く前に `anthropic-skills:yomiyasu` を読む。
- 書き込みは `update_spreadsheet` の `updateCells` で、値は `stringValue`（探索ログの候補数・追加数だけ `numberValue`）。`update_values` は数字や日付に化けるので使わない。証券コードとEDINETコードは列の書式を文字列にしてあるが、それでも `stringValue` で書く。
- 言葉一覧の行は **A〜B と D〜S と U に分けて書く**。C列（会社名の数式）とT列（黒田メモ）に書かない。新しい行は、`status.json` の「言葉一覧の次の行」から行番号を決めて `updateCells` で書く（`appendCells` は数式の列のせいで行がずれることがある）。
- 書いたら範囲を読み戻し、書いたつもりの値と Python で突き合わせる。目で見比べるだけで済ませない。
- 調べものは web_search と web_fetch（ない環境では web-fetch のサブエージェント）。候補探しの検索は `allowed_domains` で絞り、1〜3語の短い語にする。
- シートへの書き込みはサブエージェントに任せない。サブエージェントには、ページを読んで値を組み立てることだけを頼み、JSONファイルで返してもらう。

### 同梱のスクリプト（このスキルの `scripts/`）

| スクリプト | 使うとき |
|---|---|
| `prepare_run.py` | 回の最初。会社一覧・言葉一覧・除外リストの `get_values` 結果を渡すと、重複照合用の known.txt、公開判定の対象（pub.json）、点検の対象（inspect.json）、次のIDと次の行番号（status.json）を書き出す |
| `check.py` | 書き込む前の表記チェック。行を `{"tab": "言葉一覧", "A": ..., ...}` の形で並べて通し、指摘を0件にしてから書く |
| `check_pages.py` | 点検。inspect.json を渡すと、理念ページを開き直して、確認済みの言葉がそのまま載っているかを調べる |
| `edinet_fetch.py` | EDINETのチャネル。期間を指定すると、上場企業の有価証券報告書から「経営方針」の欄を取り出し、理念らしい文に印をつけて edinet_candidates.json に書き出す |

EDINETのAPIキーは、環境変数 `EDINET_API_KEY` か、黒田さんのMacのキーチェーン（サービス名 `EDINET_API_KEY`）から `edinet_fetch.py` が読む。**キーを画面、ファイル、シート、報告に出さない。** どちらにもない環境（クラウドの定期実行など）では、スクリプトが終了コード2で終わるので、EDINETのチャネルを飛ばして報告に書く。

## 定期実行

### 0. 下ごしらえ

0. `実行状況!A2:C2` を読み、設定の「実行中の目印」に従う（見送るときはここで終える）。始めるなら A2:C2 に `実行中`・開始時刻（`TZ=Asia/Tokyo date "+%Y/%m/%d %H:%M"`）・回の名前（例「2026-11-08 19:41開始の回」）を書く。**回の最後（D. 報告の前）に、A2 を `空き`、B2 を終了時刻に戻すのを忘れない。** 途中でエラーになって止めるときも戻す。
1. `入力ルール` を読む。
2. 会社一覧（`A:P`）、言葉一覧（`A:U`）、除外リスト（`A:E`）を `get_values` で読み、結果をファイルに保存して `prepare_run.py` に渡す（作業フォルダは毎回新しく作る）。
3. 空白行や重複が出たら、先に直す（同じ会社が2行あれば、言葉一覧から参照されていないほうを `非公開` にして内部メモに理由を書く）。

### A. 公開判定

対象は `pub.json`（この回の収集を始める前に `未確認` だった言葉）。会社ごとに次を行う。

1. 出典URLを開き、言葉が一字一句そのまま載っているかを確かめる。言葉の層・呼び名・項目の順番が出典と合っているかも見る。
2. その会社の言葉が出典にほかにもあり、まだ行がないときは、この場で足す（`未確認`。次の回の公開判定に回す）。
3. 結果ごとに対応し、`点検ログ` に「公開判定」として1行残す。
   - 合っている：Q列を `確認済み`、P列を今日にする。
   - 直せば合う：直して `確認済み` にし、直した点を点検ログに書く。
   - 公式の出典で確かめられない：`未確認` のまま内部メモに「保留1」「保留2」と理由を足す。保留3で `非公開`。理由がページを開けなかったことだけなら回数を増やさず「保留（サイト確認不可、日付）」と書く（追加日から14日たったら通常どおり数える）。
   - 基準に合わない（言葉ではなく事業方針の文だった、など）：`非公開` にし、内部メモに理由を書く。
4. その会社の言葉がすべて確認済みか非公開になったら、会社一覧の L列を `確認済み`、K列を今日にする。

### B. 点検（改定の発見）

この図鑑の点検は、そのまま改定の記録集めになる。

1. `check_pages.py` に `inspect.json` を渡す。
2. 「見つからない」言葉がある会社は、理念ページを自分で読む（スクリプトは JavaScript で出す文字や画像の文字を読めない）。
   - 言葉が変わっていた：古い行の K列（使い終わり）を、分かれば `2026/04` の形で、分からなければ空のまま内部メモに「改定を確認（日付）、時期は不明」と書く。古い行の Q列は `確認済み` のまま残す（言語史として公開する）。新しい言葉を新しい行で足し、L列（前の言葉のID）に古い行のIDを書く。新しい行は `未確認`（次の回の公開判定に回す）。点検ログに「改定の発見」として残す。改定を知らせるニュースリリースがあれば、それも探して出典の補足にする（時期が分かる）。
   - 価値観の項目が増えた・減った：増えた項目は新しい行で足し、なくなった項目は使い終わりを埋める。順番が変わっただけなら G列を直す。
   - ページの場所が変わっただけ：会社一覧の J列を新しいURLにする。
   - 言葉はそのまま（スクリプトが読めなかっただけ）：内部メモにその旨を書く。
3. 変化がなければ会社一覧の K列を今日にする。判断がつかなければ L列を `要更新` にして内部メモに理由を書く。点検ログに「点検」として残す。

### C. 収集

チャネルを2〜3つ選ぶ。探索ログで最近回っていないもの、直近の追加数が多いものを優先する。

| チャネル | やり方 |
|---|---|
| EDINET | `edinet_fetch.py <作業フォルダ> --from YYYY-MM-DD --to YYYY-MM-DD --limit 10 --known <作業フォルダ>/known.txt`。期間は探索ログを見て、まだ読んでいない日を選ぶ。edinet_candidates.json の `policy` を読み、理念の言葉が書かれていれば有価証券報告書を出典にして行を作る（出典URLは「書類URL」、出典の日付は提出日）。経営方針の欄に理念がない会社は、公式サイトの理念ページを探す |
| 上場企業の一覧 | JPXの上場銘柄一覧から、業種ごとに会社一覧にない会社を順に当たり、公式サイトの理念ページを探す |
| 刷新の発表 | `allowed_domains: ["prtimes.jp"]` などで「パーパス 策定」「ミッション 刷新」「バリュー 改定」などを探す。改定を見つけたら、既存の会社なら B の改定の手順で、新しい会社なら新しい言葉と、分かれば前の言葉の両方を足す |
| 芋づる | 黒田さんのコミュニティ事例図鑑（`1Bykovs905viAgkvgsHrFOKbUja2u-qwtPE7dL5CUFes` の事例一覧のC列）や、あしたの転機観測所の提供元に出てくる上場企業 |

1. 候補の会社を known.txt と除外リストに照らし、新しい会社だけ残す（会社名の表記ゆれ、「株式会社」の有無、旧社名も同じとみなす）。
2. 公式の出典を読み、会社一覧に1行、言葉一覧に言葉の数だけ行を作る。会社一覧は L `未確認`、M 今日、N `AI` か `EDINET`。言葉一覧は Q `未確認`、R 今日、S 同じ収集元。P（確認日）は空にする。
3. 理念の言葉を見つけられない会社は、除外リストに「理念の言葉が見つからない（次回以降に再検討）」と書き、E列にEDINETコードを書く。
4. `check.py` に通して指摘を0件にしてから書き、読み戻して突き合わせる。
5. `探索ログ` にチャネルごとに1行。候補数は、会社一覧にも除外リストにもなかった会社の数。

### D. 報告

この回にしたこと（公開判定の件数と結果、点検で見つけた改定、足した会社と言葉の数、チャネルごとの候補数と追加数）、保留にした理由、黒田さんに決めてほしいことを短くまとめる。**改定を見つけた会社は、会社名と新旧の言葉を必ず報告に書く**（研究所の発信のネタになる）。

## 週次ふりかえり

1. 直近7日の探索ログ・点検ログ・言葉一覧の追加日から、チャネルごとの候補数と追加数、公開判定の結果、見つけた改定を数える。
2. 言葉一覧の確認済みを、層ごと・呼び名ごとに数える（「ミッション」「パーパス」「志」などの呼び名の分布は、研究所の分析の元になる）。
3. 設定の見直し案（件数、頻度、チャネル）と、入力ルールで迷った点を、黒田さんへの提案として最大3つまで出す。この文書と設定は自分で書き換えない。
